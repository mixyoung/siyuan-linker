# SiYuan Linker 工作空间、笔记本与文档同步架构设计

> 状态：设计基线，部分能力尚未实现  
> 更新日期：2026-09-07  
> 适用版本：SiYuan Linker 0.4.x 及后续版本

## 1. 文档目的

本文定义 SiYuan Linker 后续同步能力的产品边界、统一模型、技术架构、安全约束和实施路线。

规划中的产品分为两类：

1. **镜像同步**：通过配对、谱系、基线和冲突检测，在两个工作空间之间持续维护内容关系；
2. **一次性复制**：将内容导入另一个独立工作空间，生成新 ID，之后不建立同步关系。

镜像同步按范围分为：

- 工作空间级同步；
- 笔记本级同步；
- 文档或文档树级同步。

当前已经实现的主要能力包括：文档级**精确 ID 镜像**第一阶段、基于思源原生归档的**独立副本**、完整工作空间导出/导入，以及完整克隆后的目标身份接管。完整克隆目前仍由多个独立操作组成，尚不是自动化向导；本文其余内容是后续开发目标，不能当作当前版本已经提供的功能。

## 2. 核心术语

### 2.1 同步范围

同步范围定义一次同步任务管理的内容边界：

- `workspace`：工作空间内容；
- `notebook`：一个或多个指定笔记本；
- `document`：指定文档或文档树。

### 2.2 同步方向

同步方向与触发方式必须分开：

- `push`：本地单向推送到目标端；
- `pull`：目标端单向拉取到本地；
- `bidirectional`：双向比较并同步双方单边变化。

双向同步不等于双方无条件互相覆盖。双方同时修改同一对象时必须产生冲突。

### 2.3 触发方式

- `manual`：用户查看计划并手动执行；
- `scheduled`：按照时间计划执行；
- `event-driven`：检测到变化后执行，作为远期能力。

第一阶段只实现手动触发。定时和事件触发不得改变冲突与安全语义。

### 2.4 谱系

谱系用于证明两个工作空间、笔记本或文档集合是由用户明确建立的同步关系。谱系不是身份认证，也不能包含 API Token。

### 2.5 基线

基线是上一次成功同步后双方共同确认的状态。双向同步和安全单向同步都必须通过“源端当前状态、目标端当前状态、共同基线”进行三方比较。

### 2.6 逻辑路径

逻辑路径是忽略端点特有容器 ID 后的同步路径。

例如两个笔记本 ID 不同时：

```text
本地物理路径：
data/local-notebook-id/parent-id.sy/child-id.sy

远程物理路径：
data/remote-notebook-id/parent-id.sy/child-id.sy

共同逻辑路径：
parent-id.sy/child-id.sy
```

## 3. 产品结构

建议最终界面采用以下结构：

```text
SiYuan Linker

同步配置
├─ 工作空间内容镜像
│  ├─ 单向推送
│  ├─ 单向拉取
│  └─ 双向同步
│
├─ 笔记本同步
│  ├─ 选择源笔记本
│  ├─ 选择、创建或映射目标笔记本
│  └─ 单向或双向
│
└─ 文档精确镜像
   ├─ 仅当前文档
   ├─ 当前文档及全部子文档
   └─ 单向或双向

一次性工具
├─ 一次性复制（生成新 ID）
├─ 完整工作空间克隆
└─ 接管完整克隆目标
```

独立副本不再作为一种“同步模式”展示，而应定位为一次性复制工具。

## 4. 统一同步配置模型

```ts
interface SyncProfile {
    id: string;
    name: string;

    scope: "workspace" | "notebook" | "document";
    direction: "push" | "pull" | "bidirectional";
    trigger: "manual" | "scheduled";

    conflictPolicy:
        | "stop"
        | "authority-wins"
        | "manual";

    conflictAuthority?:
        | "direction-source"
        | "local"
        | "remote";

    deletionPolicy:
        | "ignore"
        | "archive-and-delete"
        | "mirror-delete";

    localWorkspaceId: string;
    remoteWorkspaceId: string;

    notebookMappings: NotebookMapping[];
    documentRoots: DocumentRootSelection[];
}

interface NotebookMapping {
    localNotebookId: string;
    remoteNotebookId: string;
}

interface DocumentRootSelection {
    documentId: string;
    includeDescendants: boolean;
}
```

`manual` 不是与 `push`、`pull`、`bidirectional` 并列的方向，而是可以和任一方向组合的触发方式。

`localWorkspaceId` 和 `remoteWorkspaceId` 是配置中的稳定端点角色；每次运行还必须解析出 `effectiveSource` 和 `effectiveDestination`：

- 推送：本地是有效源端，远程是有效目标端；
- 拉取：远程是有效源端，本地是有效目标端；
- 双向：三方比较只为无冲突的单边变化确定写入方向；双方分叉时，在选择权威端或完成手动决策之前不存在有效源端和目标端。

冲突解决后，权威端或用户选择的保留端才成为该对象的有效源端，另一端成为有效目标端。冲突策略、pending operation 所有权、删除来源和确认文案都必须使用这一运行期语义，不能把“本地”固定等同于“源端”。任何覆盖确认都必须明确显示将保留哪一端、覆盖哪一端。

## 5. 统一同步执行流程

所有同步范围使用同一套状态机：

1. 验证连接、版本、谱系和能力；
2. 获取两端只读快照；
3. 读取共同基线和删除墓碑；
4. 生成同步计划；
5. 展示创建、更新、移动、删除、跳过和冲突项；
6. 用户确认；
7. 在两端写入同一 pending operation；
8. 按依赖顺序执行操作；
9. 每一步进行写后读取验证；
10. 全批次重新获取快照；
11. 双端提交共同基线并清除 pending；
12. 失败时执行所有权受限的尽力回滚。

规划阶段不得写入文档、附件或谱系成功基线。

## 6. 同步计划

```ts
interface SyncPlan {
    creates: SyncAction[];
    updates: SyncAction[];
    moves: SyncAction[];
    deletes: SyncAction[];
    noops: SyncAction[];
    conflicts: SyncConflict[];
}
```

执行前至少显示：

```text
将创建 2 个笔记本
将创建 18 篇文档
将更新 5 篇文档
将移动 1 篇文档
将删除 3 篇文档
发现 2 个冲突
```

存在未解决冲突时，默认禁止执行整个批次。

## 7. 冲突模型

### 7.1 三方比较

| 本地状态 | 远程状态 | 相对基线 | 结果 |
|---|---|---|---|
| 未变化 | 未变化 | 相同 | 跳过 |
| 已变化 | 未变化 | 本地变化 | 推送 |
| 未变化 | 已变化 | 远程变化 | 拉取 |
| 双方变化且结果相同 | 双方变化 | 已收敛 | 更新基线 |
| 双方变化且结果不同 | 双方变化 | 分叉 | 冲突 |
| 一边删除、另一边未修改 | 删除 | 单边变化 | 按删除策略处理 |
| 一边删除、另一边已修改 | 删除与修改 | 分叉 | 冲突 |

不能使用两端 `updated` 时间直接判断最新版本。思源的更新时间和 SQL 索引存在实例差异与写入延迟。

### 7.2 冲突策略

- `stop`：发现冲突后停止，推荐默认值；
- `authority-wins`：明确确认后以稳定权威端覆盖另一端；
- `manual`：用户逐项选择本地覆盖远程、远程覆盖本地或跳过。跳过对象不得推进其共同基线。

权威端规则：

- 单向推送只能使用 `direction-source`，即本地权威；
- 单向拉取只能使用 `direction-source`，即远程权威；
- 双向任务不能使用 `direction-source`，必须在配置中明确选择 `local` 或 `remote`；
- 单向任务不能通过冲突策略反向写回，否则会违反配置的同步方向；
- 如果用户决定保留单向任务的目标端内容，只能将该对象标记为跳过或未解决冲突，不能推进共同基线。

已经存在共同基线的目标端独立修改不得被普通“首次采纳源端”确认绕过。

## 8. 删除模型

双向同步必须记录删除墓碑，否则无法区分“从未存在”和“曾经存在但被删除”。

```ts
interface DeletionTombstone {
    objectType: "notebook" | "document" | "asset";
    objectId: string;
    deletedByWorkspaceId: string;
    deletedAt: string;
    previousFingerprint: string;
}
```

删除策略：

- `ignore`：不传播删除；首次发现删除时仍记录一条“未解决”的删除墓碑，同时保留删除前的对象基线，并将该对象排除在本批次共同基线推进之外；
- `archive-and-delete`：先在插件目录保存恢复信息，再删除；
- `mirror-delete`：权威镜像模式下同步删除。

批次级 generation 可以继续推进，但被跳过或忽略删除的对象必须继续保留原对象基线与未解决状态，直到双方重新收敛或用户明确处理。附件位于工作空间全局 `data/assets`，删除前必须检查整个工作空间的引用，不能按单个笔记本或文档的局部结果直接删除。

## 9. 工作空间级同步

### 9.1 定义

工作空间级同步维护两端工作空间的内容镜像，第一阶段包括：

- 笔记本；
- 文档和普通块；
- 文档层级；
- 安全的根自定义属性；
- 附件；
- 经过明确支持的笔记本配置。

以下内容不属于在线工作空间内容镜像：

- 临时文件和缓存；
- 内核数据库文件本身；
- 历史记录；
- 同步仓库内部状态；
- 操作系统级配置；
- 未声明支持的第三方插件数据。

如果要求工作空间目录字节级一致，应使用思源官方同步或停机文件系统复制，而不是在线插件 API。

### 9.2 首次完整克隆

当前可复用思源原生全量接口：

```text
/api/export/exportData
→ 下载 /export/...zip
→ /api/import/importData
```

建议首次克隆流程：

```text
确认目标为空白或可丢弃
→ 导出源工作空间
→ 导入目标工作空间
→ 接管完整克隆目标（归档复制来的谱系、旋转目标 workspaceId 并清空活动谱系）
→ 显式建立配对
→ 获取两端完整快照
→ 建立第一次共同基线
```

其中，完整导出/导入、目标身份接管和显式配对已经分别实现；目标空白度自动检查、串联这些步骤的克隆向导和第一次完整共同基线仍是计划能力。全量导入不等于自动配对。完整克隆可能复制插件身份与旧谱系，因此必须执行目标接管。

### 9.3 后续增量同步

首次克隆完成后应使用增量引擎，而不是反复全量导入：

- 枚举两端笔记本；
- 扫描所有文档树；
- 比较共同基线；
- 生成全工作空间计划；
- 处理新增、修改、移动、重命名和删除；
- 汇总全工作空间冲突；
- 成功后提交新基线。

### 9.4 公开 API 限制

思源 v3.8.2 没有安全的“创建指定 ID 笔记本”公开 API。因此首次克隆后新增的笔记本有两种选择：

1. 建立本地和远程笔记本 ID 映射；
2. 如果要求笔记本 ID 也严格相同，则重新进行受控完整克隆或等待官方能力。

不得通过直接重命名 `data/<notebookId>` 目录或修改数据库字段实现在线 ID 修改。

## 10. 笔记本级同步

### 10.1 定义

笔记本级同步以一个笔记本的全部内容为边界，包括：

- 所有根文档；
- 所有子文档；
- 文档和普通块 ID；
- 文档标题、层级和逻辑路径；
- 安全自定义属性；
- 被支持的附件关系；
- 被明确支持的笔记本配置。

空笔记本也必须能够建立同步配置，不能依赖选中文档来推断笔记本关系。

### 10.2 初次建立方式

#### 相同 ID 自动匹配

如果两端已有同 ID 笔记本，自动建立：

```text
local-notebook-id ↔ local-notebook-id
```

#### 创建目标笔记本并映射

如果目标端不存在对应笔记本：

1. 调用思源接口创建普通目标笔记本；
2. 记录思源生成的目标笔记本 ID；
3. 建立双端映射；
4. 使用映射后的目标 ID 创建文档；
5. 使用源端文档 ID 和父文档 ID 保持文档树身份。

```json
{
  "localNotebookId": "20240922091315-yy1vlf4",
  "remoteNotebookId": "20260907123000-abcdefg"
}
```

#### 映射到已有目标笔记本

允许用户选择已有目标笔记本，但必须先检查：

- 同 ID 文档和块冲突；
- 相同逻辑路径上的不同文档；
- 加密状态；
- 当前 pending operation；
- 已有映射是否形成一对多或多对一冲突。

默认推荐创建新的空目标笔记本。

### 10.3 路径和身份

笔记本映射模式保持：

- 文档 ID；
- 普通块 ID；
- 父子关系；
- 笔记本内部相对路径；
- HPath 和标题层级；
- 可验证的块引用关系。

允许变化的是端点笔记本 ID 和完整物理路径的笔记本前缀。

一个源笔记本在同一配对中只能映射到一个目标笔记本，反向拉取使用同一映射的逆方向。

### 10.4 单向同步

提供：

- **安全单向同步**：目标端发生独立变化时停止；
- **权威镜像**：用户明确确认后以源端状态创建、更新、移动和删除目标内容。

### 10.5 双向同步

第一阶段仅支持普通未加密文档，并依赖：

- 双端共同基线；
- 删除墓碑；
- 文档移动记录；
- 冲突列表；
- 双端 pending journal；
- 双端写后验证。

属性视图、加密笔记本、双方同时移动同一文档和跨笔记本移动作为后续能力。

## 11. 文档级同步

### 11.1 当前能力

当前精确 ID 镜像已经提供：

- 选中文档精确创建或更新；
- 缺失祖先按层级创建；
- 文档 ID 和普通块 ID 保持；
- 三方基线；
- 写前冲突检查；
- pending journal；
- 写后 DOM、SQL、属性、路径和附件验证；
- 所有权受限的尽力回滚。

当前限制包括：

- 两端必须已有同 ID 笔记本；
- 不支持笔记本映射；
- 不支持属性视图和加密笔记本；
- 不自动处理文档移动和重命名；
- 不传播删除；
- 不自动同步全部子文档。

### 11.2 后续范围选择

界面增加：

```text
同步范围：
○ 仅当前文档
● 当前文档及全部子文档
```

#### 仅当前文档

同步当前文档内容。缺失祖先仍需创建，避免文档落入错误根路径；已有且未选择的祖先只验证位置，不覆盖内容。

#### 当前文档及全部子文档

将选中文档作为同步根，递归纳入全部后代文档，按父到子顺序创建或更新，按子到父顺序删除或回滚。

### 11.3 后续增强

- 使用笔记本映射；
- 文档移动和重命名；
- 删除墓碑；
- 文档树自动展开；
- 同步计划预览；
- 手动双向同步；
- 更清晰的冲突差异展示。

## 12. 独立副本的定位

### 12.1 设计初衷

独立副本是一种一次性复制，不属于同步协议：

> 将内容复制到另一个无关工作空间。插件会创建或复用一个目标容器笔记本，由思源为导入的文档、块和属性视图生成新 ID；复制完成后双方不维持谱系、基线或同步关系。

建议在界面中改名为：

> **一次性复制（生成新 ID）**

### 12.2 使用场景

#### 向其他人交付内容

对方获得可独立编辑的副本，双方后续修改互不影响。

#### 从模板创建项目

将项目模板复制成多个独立实例，避免模板与实例共享 ID 或同步关系。

#### 在无关工作空间间迁移资料

个人知识库与公司知识库没有共同来源，也不需要建立长期配对。

#### 避免 ID 冲突

目标端存在相同 ID 但并非同源内容时，通过新 ID 让两份内容安全共存。

#### 复制复杂原生依赖

当前精确镜像不支持属性视图。思源原生 `.sy.zip` 导入更适合一次性携带属性视图、PDF 标注、依赖文档和资源。

#### 创建阶段性快照

生成不会继续随源内容变化的交付版、审计版或归档副本。

#### 改变目标组织结构

用户只关心内容，不要求保持源笔记本、路径和 ID，可在目标端重新组织。

### 12.3 当前实现

当前独立副本：

1. 按源笔记本对所选文档分组；
2. 在目标端创建或复用以源笔记本名称和 ID 组成名称的容器笔记本；
3. 调用 `/api/export/exportSY` 或 `/api/export/exportSYs`；
4. 下载原生 `.sy.zip`；
5. 调用 `/api/import/importSY` 导入目标笔记本；
6. 由思源生成新的内部 ID。

原生归档可能包含选中范围以外的引用文档、子文档、属性视图、PDF 标注和相关资源，界面必须继续明确提示。

## 13. 统一技术架构

### 13.1 端点层

负责：

- 本地和远程连接；
- Token 和 HTTPS 策略；
- 思源版本及能力检测；
- API 响应校验；
- 重试和读回验证。

### 13.2 范围适配器

```ts
interface SyncScopeAdapter {
    captureSource(): Promise<ScopeSnapshot>;
    captureDestination(): Promise<ScopeSnapshot>;
    buildLogicalPath(item: SyncItem): string;
    validateCapabilities(): Promise<void>;
}
```

实现：

- `WorkspaceScopeAdapter`；
- `NotebookScopeAdapter`；
- `DocumentScopeAdapter`。

### 13.3 同步规划器

规划器只负责比较和生成动作，不执行写入：

- 快照规范化；
- ID 和路径映射；
- 三方比较；
- 冲突分类；
- 动作依赖排序；
- 风险摘要。

### 13.4 同步执行器

负责：

- pending journal；
- 每次变更前的 pending 所有权确认；
- 附件、祖先和文档的依赖顺序；
- 写后验证；
- 失败回滚；
- 新基线提交；
- 文件树刷新。

### 13.5 身份与映射层

谱系至少记录：

- 本地和远程 workspaceId；
- pairId；
- 笔记本映射；
- 文档同步根；
- 同步方向和策略；
- 当前 generation；
- 共同基线；
- 删除墓碑；
- pending operation。

谱系文件不保存 Token。

### 13.6 调度层

后续负责：

- 手动执行；
- 定时任务；
- 防止同一配置并发运行；
- 最近执行状态；
- 失败重试；
- 用户通知。

在没有可靠远程变更事件订阅的情况下，自动双向同步优先采用定时扫描，不宣称实时同步。

## 14. 安全边界

所有同步范围必须遵守：

- API 成功只能视为暂定成功，必须读回验证；
- 写前完成整批预检；
- 冲突默认停止；
- 删除默认不传播；
- pending 未清除时禁止开始新操作；
- 目标端未知内容不得被回滚覆盖；
- 附件删除需要全工作空间引用证明；
- 远程 Token 只保存在思源 Secrets；
- 谱系和日志不得包含凭据；
- 远程 HTTP 默认禁止；
- 全量导入、权威覆盖和删除传播的目标设计必须使用强确认：确认框需显示有效源端、有效目标端、范围和不可逆后果；高风险操作应进一步要求输入确认短语；
- 当前版本的完整克隆接管已有确认短语，但全量推送/拉取仍是普通确认框，因此“全量导入强确认”属于待实现安全增强；
- 不把尽力回滚描述成原子事务。

## 15. 实施路线

### 第一阶段：统一产品模型

- 将范围、方向和触发方式分离；
- 将独立副本移动到“一次性复制”；
- 定义 `SyncProfile`；
- 增加同步计划模型；
- 保持当前文档精确镜像兼容。

### 第二阶段：笔记本映射

- 相同 ID 自动匹配；
- 创建新目标笔记本；
- 映射到已有目标笔记本；
- 双端保存并验证映射；
- 使用逻辑相对路径比较；
- 支持正向和反向解析；
- 检查全局文档和块 ID 冲突。

这是最优先的新增能力。

### 第三阶段：文档树同步

- 将当前已实现的“仅当前文档”和“缺失祖先补全”重构到统一范围适配器，保持现有行为兼容；
- 新增“当前文档及全部子文档”；
- 新增移动和重命名；
- 新增删除墓碑；
- 新增执行前计划预览。

### 第四阶段：笔记本全量单向同步

- 扫描整个笔记本；
- 新增、更新、移动和删除；
- 安全单向模式；
- 源端权威模式；
- 目标端漂移检查。

### 第五阶段：笔记本双向同步

- 双方单边变化自动传播；
- 双端变化冲突；
- 删除与修改冲突；
- 手动冲突处理；
- 双端基线提交。

### 第六阶段：工作空间首次克隆标准化

- 完整克隆向导；
- 目标端安全检查；
- 自动接管克隆身份；
- 显式配对；
- 第一次完整基线。

### 第七阶段：工作空间增量同步

- 所有笔记本统一计划；
- 新笔记本映射；
- 笔记本删除；
- 全局附件引用；
- 工作空间级冲突汇总。

### 第八阶段：定时和后台同步

- 定时单向同步；
- 定时双向扫描；
- 失败重试；
- 执行历史；
- 并发锁和通知。

## 16. 分阶段验收标准

### 16.1 第二阶段：笔记本映射基础设施

笔记本映射完成时，至少满足：

- 可以将源笔记本映射到不同 ID 的目标笔记本；
- 可以在目标端创建新的空笔记本并自动记录映射；
- 两端谱系对映射记录完全一致；
- 正向推送和反向拉取使用同一映射；
- 笔记本内部文档相对路径一致；
- 文档 ID 和普通块 ID 保持；
- 缺失祖先按父到子顺序创建；
- 已有未选择祖先不被覆盖；
- 同 ID 文档或块被其他内容占用时，整批写前停止；
- 目标端不同内容默认不覆盖；
- 属性视图和加密笔记本继续在写前拒绝；
- 最终目标端快照经过完整读回验证；
- 失败不会推进成功基线；
- 独立副本和完整工作空间克隆行为不被改变。

### 16.2 第四阶段：笔记本全量单向同步

在第二阶段映射能力之上，还必须满足：

- 自动枚举同步笔记本内全部根文档和后代文档；
- 新增、更新、移动、重命名和删除全部进入统一计划；
- 安全单向模式遇到目标端漂移时停止；
- 权威镜像模式逐项显示将覆盖和删除的内容并执行强确认；
- 空笔记本也能同步名称和受支持配置；
- 笔记本同步完成后，两端逻辑文档树和普通块身份集合一致。
