# SiYuan Linker

**简体中文** · [English](README_en_US.md)

在本地 SiYuan 工作空间与当前目标 SiYuan 服务之间传输所选笔记或工作空间归档。

> [!IMPORTANT]
> 本插件要求 **SiYuan 3.8.2 或更高版本**。实现基于 3.8.2 内核 API 能力，但精确镜像仍需针对实际使用的 SiYuan 版本、部署拓扑、代理、笔记本和数据进行在线集成验证。单元测试和构建通过不能替代真实内核测试。

## 部署方式

只需在操作 UI 的**本地 SiYuan 端**安装并启用插件。远程端无需安装插件，但必须能够访问其 SiYuan 内核 API，并使用具有管理员级内核访问能力的 API Token。请把 Token 存入本地 SiYuan Secret，绝不要直接写入插件设置、URL、日志或截图。

非回环目标默认要求 HTTPS。可为可信局域网显式启用 HTTP，但 Token、笔记、元数据和归档会以明文传输。浏览器部署还可能受到 CORS、混合内容和 Private Network Access 策略限制。

## 笔记传输模式

工作空间、笔记本和文档三级同步的目标架构、产品边界及实施路线详见[同步架构设计](docs/design/workspace-notebook-document-sync-architecture.md)。文档中标注的规划能力不代表当前版本已经实现。

### 精确 ID 镜像

精确 ID 镜像用于两个已经明确配对且具有共同来源的工作空间。它保留源端笔记本路径以及文档/块 ID，使依赖稳定 ID 的链接仍有机会保持有效。

每次精确传输前，插件都会验证两端谱系，然后执行保守的预检。遇到谱系不匹配、待处理操作、路径不匹配、全局 ID 冲突、资源哈希冲突或三方内容冲突时会中止。目标写入采用尽力的所有权验证与回滚；它不是数据库事务。

精确 ID 镜像当前：

- 要求两端 SiYuan 版本完全一致，且两端存在相同 notebook ID；
- 支持所选文档，并在保留路径所需时创建缺失的祖先文档；
- 不修改已经存在但未选择的祖先文档；
- 拒绝加密笔记本和绑定属性视图的文档；
- 不支持文档重命名、文档移动或笔记本重映射；
- 目标端独立修改时中止，不进行冲突合并；
- 在写入验证成功后，内核允许时刷新目标文件树。

**首次传输且没有共同基线时采用保守策略：**如果目标端已经存在同 ID 文档，只有其完整指纹与源端一致时才接受，否则直接判定为冲突。只有两端验证出相同最终状态后，插件才会记录共同基线。 当插件报告这类首次同步冲突时，会提供显式确认的“以源端版本覆盖”来解决受影响文档并重建基线；已有基线时，目标端的本地修改仍会作为冲突中止。

### 一次性复制（生成新 ID）

一次性复制使用 SiYuan 原生文档导出/导入归档，适用于互不关联的工作空间，**不要求配对**。导入时 SiYuan 会生成新的文档、块和属性视图 ID。

原生归档范围可能大于界面中的选择。根据源端数据和导出设置，它可能包含引用文档、子文档、关联属性视图、PDF 标注、资源和其他支持数据。插件会在导入前的确认框中明确提示这一扩展范围。

### 全量数据传输

全量推送和拉取始终使用 SiYuan 原生全数据归档，不受所选笔记传输模式影响。它们不会创建配对，也不是精确 ID 镜像。仅应在已备份的空白或一次性目标工作空间中使用：导入可能覆盖或混合数据，失败后也可能留下部分写入。

## 镜像谱系

配对会在**每个工作空间**写入两个插件自有文件：

- `data/storage/petal/siyuan-linker/workspace-identity.json`：稳定的随机工作空间身份，用于区分两端。重置对端配对不会删除此身份。
- `data/storage/petal/siyuan-linker/mirror-lineages.json`：对端记录，包含配对 ID、本地与对端工作空间 ID、配对时两端共同存在的 notebook ID、已验证文档基线，以及可能存在的待处理镜像操作。

这些文件不包含 API Token。除非完全理解谱系后果，否则不要复制、手工编辑或选择性还原它们。重复的工作空间身份、单边对端记录、分歧基线或待处理操作都会有意阻止精确镜像，直至完成检查和处理。

## 配对流程

1. 配置并验证当前目标源连接。
2. 只有在两个工作空间需要共享稳定 ID 时，才选择**精确 ID 镜像**。
3. 在插件设置中点击**配对当前目标源**。配对始终由用户主动触发，绝不会自动执行，也不会与全量传输绑定。
4. 检查状态摘要：配对 ID、本地与远程工作空间 ID、允许的笔记本数，以及待处理或不匹配原因。
5. 切换目标、恢复数据或排查拒绝原因后，使用**验证当前配对**。
6. 备份两端工作空间，再推送当前笔记或拉取所选笔记。
7. 只有在阅读确认提示后才使用**重置当前配对**。存在待处理操作时，普通重置会先拒绝；界面可在再次强确认后执行应急强制重置。强制重置成功完成时会在两端插件数据目录归档当前谱系并清除 pending，但不会恢复或删除已经部分写入的文档；跨端操作也不是原子事务，中断时可能只完成一端，因此必须先备份，完成后重新验证配对状态并人工核对目标端内容。

通过完整工作空间克隆创建的目标起初会与源端拥有相同的工作空间身份，普通配对会有意拒绝这种情况。仅当所选目标已经确认是源端的完整克隆时，使用单独的**接管全量克隆目标**操作，接受破坏性警告并输入完整确认短语。该操作会归档目标端复制来的谱系，只轮换目标身份并清空其当前复制谱系，而且不会自动配对。请检查归档路径，然后再明确执行配对。

配对只记录配对当时两端共同存在的 notebook ID。如果所需 notebook ID 未同时存在，请先准备工作空间和笔记本，不要期望精确镜像自动重映射。

## 配置

1. 在远程 SiYuan 的**设置 → 关于**中找到 API Token。
2. 在运行插件的本地 SiYuan 中打开**设置 → 密钥与变量**，创建 Secret，例如 `SIYUAN_LINKER_TARGET_1_TOKEN`，值为远程 Token。
3. 在插件设置中填写目标 URL 和 Secret 名称，不要填写 Token 本身。
4. 选择当前目标源并点击**验证**。

89	## 限制与安全模型
90	
91	- SiYuan 没有向本插件提供官方的跨工作空间 ACID 事务、跨进程租约，也没有提供可冻结并发编辑的文档化维护锁。插件只在当前插件进程内串行化配对、重置、克隆接管和精确镜像；其他浏览器窗口、插件进程、设备或外部 API 客户端不受此保护。精确传输期间请停止编辑，并确保只有一个操作者/进程执行。
92	- 尽力回滚只会在验证内容确属本次操作后执行恢复或删除。遇到无法确认所有权的并发变化时，插件会保留现状并报告，而不是破坏性覆盖。
93	- 文档写入失败前新建的资源不会仅凭字节相同就被删除，而会作为无害孤立资源保留。错误会列出残留资源路径供手动检查和清理；文档回滚验证成功时仍可清除待处理谱系。
94	- 待处理谱系记录是安全信号，不代表可以盲目重试。普通重置会拒绝待处理记录；应优先检查两端工作空间并完成恢复或经验证的回滚。只有无法正常恢复时，才使用配对流程中说明的应急强制重置，并在操作后重新验证两端状态。
95	- 精确镜像不进行冲突合并，不支持文档重命名、移动、笔记本重映射、加密笔记本或绑定属性视图的文档。
96	- 一次性复制与全量导入继承 SiYuan 原生归档 API 的范围和行为。
- 每次写入前都应备份两端，并确认源端、目标端、当前目标源、传输模式和配对状态。

## 本地安装

将 `package.zip` 解压到：

```text
<SiYuan 工作空间>/data/plugins/siyuan-linker/
```

确保 `plugin.json`、`index.js`、`index.css` 位于目录根部，然后重启 SiYuan 或刷新插件列表。插件只需安装在本地操作端；远程端仅需开放管理员内核 API。
